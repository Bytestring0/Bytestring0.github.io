# 先记住这五件事

1. **随手记**：按 `Ctrl+Alt+I`，输入一句话，回车，自动追加到 [[收件箱]]。
2. **写完整笔记**：按 `Ctrl+Shift+N`，选标题、分类和类型，然后直接写。
3. **找笔记**：知道标题按 `Ctrl+O`；只记得正文关键词按 `Ctrl+Alt+F`。
4. **叫 Pi 帮忙**：按 `Ctrl+Shift+A`，先用 `/model` 选择模型，再输入 `/current 帮我整理这篇笔记`。
5. **发博客**：准备好后切换 `publish: true`，检查本地预览，停止预览，再手动部署。

这篇手册的 `publish: false`，只在本地笔记和 Git 中保存。[[00-博客工作台|打开博客工作台]]。

## 一份文件，两个编辑器

博客项目：`D:\AstroBlog\mizuki`。Obsidian 仓库：`D:\AstroBlog\mizuki\src\content\posts`。

VS Code 与 Obsidian 打开的是同一份 Markdown。保存后，另一个编辑器会看到文件变化。尽量不要同时在两个编辑器里改同一段文字。

左侧文件列表就是 posts。分类是实际文件夹，例如 `微电子笔记`、`工科基本功`、`EDA`、`杂谈`。你可以新建、移动或重命名；在 Obsidian 内移动时会更新笔记链接。VS Code 移动文件时，需要自己检查链接。

新笔记默认进入 posts 根目录；工作台的新建窗口可以直接选分类。粘贴或拖入的图片自动放到**当前笔记所在目录的 `images` 子文件夹**，不存在时自动创建；绘图放在 `绘图`，日记放在 `日记`。应用设置和插件在隐藏的 `.obsidian` 中。

例如 `微电子笔记/MOS复习.md` 中粘贴图片，会保存到 `微电子笔记/images/`；根目录笔记的图片放到 `posts/images/`。同一分类下的笔记共用该分类的 images 文件夹，文件名冲突由 Obsidian 自动避开。图片移动后请检查链接；原有 `附件` 中的图片仍可继续引用。

新链接使用相对路径，图片嵌入形如 `![[images/图片名.png]]`，Obsidian 和博客都能解析。

Obsidian 使用与 VS Code 对齐的 Moonlight 配色、Maple Mono 字体和猫猫背景。博客保持“无壁纸”配置。

背景图片保存在 `.obsidian/snippets/maomaolove.png`，由 Mizuki 工作台在每次启动时获取有效的图片地址。保留工作台插件与 `moonlight-background` CSS 片段启用；不要把某次启动的 `app://...` 地址写死在 CSS 中，否则重启后可能失效。

## 三种快速写作方式

### 只有一句想法：收件箱

按 `Ctrl+Alt+I`，输入“明天整理 MOS 管工作区条件”，回车。收件箱会增加一行：

```text
- 2026-10-09 22:30 明天整理 MOS 管工作区条件
```

不需要先起标题、选目录。每天花几分钟把有价值的条目搬到正式笔记，完成的条目改成任务或删除。收件箱保持不公开。

### 课堂或实验：带结构的新笔记

按 `Ctrl+Shift+N`，填写标题，例如“模拟电路 第三讲”，选择 `微电子笔记` 和“课程笔记”。创建后已有“本节要点、定义与推导、例题、待解决问题”。实验类型已有“目的、条件与电路、数据与结果、分析与结论”。

先用短句记结论，没跟上的内容写成 `- [ ] 待补：……`，课后再让 Pi 整理。不要为了排版中断听课。

`Ctrl+N` 也能快速新建，工作台会给普通 Markdown 笔记补上默认不公开的属性。

### 日记或随笔：先写，再决定公开

按 `Ctrl+Alt+D` 打开今天的日记，在“记录”下面写。需要成为文章时，用工作台新建“随笔 / 博客文章”，再搬入相应内容。

已有笔记需要模板时，按 `Ctrl+Alt+T`，选择 `模板/普通笔记`、`模板/课程笔记`、`模板/实验记录` 或 `模板/日记`。这些是内置 Templates 的 `{{title}}`、`{{date}}` 模板，适合空白笔记；已有属性时避免重复插入整段 YAML。工作台新建已套用结构，不必再插模板。

Templater 适合以后需要动态脚本模板时使用，其语法是 `<% ... %>`，和上述内置模板语法不同。

## Markdown、链接与整理技巧

```markdown
## 小信号模型

**结论**：先确定工作点，再建立小信号等效电路。

- 已理解：跨导的定义
- [ ] 待补：输出电阻推导

相关概念：[[微电子笔记/MOS跨导|MOS 跨导]]
跳到标题：[[微电子笔记/MOS跨导#定义]]
跳到块：[[微电子笔记/MOS跨导#^gm-definition]]
引用一节：![[微电子笔记/MOS跨导#定义]]

> [!tip] 检查步骤
> 写清假设、单位和适用范围。

> [!warning]- 点击展开待检查内容
> 这里默认折叠。
```

输入 `[[` 后选已有笔记；同名笔记用完整分类路径。`|显示名称` 只改变显示文字。段落末尾添加 `^块ID` 后可以精确引用那个段落。

右侧“反向链接”帮助找到引用当前笔记的其他笔记；“大纲”适合在长笔记中跳到标题；图谱查看整体连接。把常用笔记加到书签，比每次翻文件夹更快。命令面板里的“笔记重组 / Note composer”可以把选中的长段落拆为独立笔记。

编辑区的 `/` 是 Obsidian 的编辑命令菜单；**Pi 对话框里的 `/model` 才是助手命令**。

## 公式：命令补全 + LaTeX Suite

行内公式写 `$g_m$`；独立公式用两行 `$$` 包住：

```latex
$$
g_m = \frac{\partial I_D}{\partial V_{GS}},\qquad
A_v \approx -g_m(R_D \parallel r_o)
$$
```

**LaTeX Complete 已启用**：在 `$...$` 或 `$$...$$` 内输入反斜线和字母，例如 `\fra`、`\alp`、`\par`，会显示命令候选及中英文说明。方向键选择，`Tab` 或 `Enter` 确认，`Esc` 关闭。它补全命令名称；`\frac` 的 `{分子}{分母}` 等参数需要继续填写。普通正文、行内代码和 fenced 代码块里不触发。

例如输入 `$\fra$` 并把光标放在 `a` 后面，确认 `\frac`，最后写成 `$\frac{I_D}{V_{GS}}$`。编辑视图才能输入，阅读视图里的示例代码不会触发补全。

LaTeX Suite 负责更快的片段展开，例如默认 `//` 自动变成分数模板，`sq` 自动变成平方根模板，`sr` 自动变成平方 `^{2}`；`Tab` 在模板占位之间跳转，`Shift+Tab` 返回。下面的微电子片段需要在 `$...$` 或 `$$...$$` 内输入，再按 `Tab` 展开：

| 输入 | 展开 |
| --- | --- |
| `gm` | `g_m` |
| `vgs` | `V_{GS}` |
| `vds` | `V_{DS}` |
| `vth` | `V_{TH}` |
| `ids` | `I_{DS}` |
| `cgs` / `cgd` | `C_{GS}` / `C_{GD}` |
| `ro` | `r_o` |

片段配置在 `.obsidian/snippets/microelectronics.js`。中文输入法正在组词时不会触发片段；不展开时先切换英文输入，再确认光标位于数学模式。

## Pi 助手：模型、会话与命令

按 `Ctrl+Shift+A` 打开右侧 Pi。使用本机 Pi CLI 的模型和登录配置。默认 **Edit** 模式可以读写笔记，不启用 shell；只想审阅时，在 Pi 设置中改为 **Review / read-only**。这属于工具权限选择，不是操作系统沙箱。

输入命令时有补全，方向键选择，`Tab` 或 `Enter` 接受建议。输入框内 `Enter` 发送，`Shift+Enter` 换行。建议先 `/model` 选模型，再 `/status` 检查设置。

### 本机控制命令

下面的命令已由 Mizuki 工作台补齐，在本机执行，不把控制命令发给模型。工作台插件和 Pi Agent 插件都需要保持启用。

| 命令 | 用法 |
| --- | --- |
| `/model` | 打开可搜索的模型选择器 |
| `/model provider/model-id` | 切换到指定提供方的模型；只写模型 ID 时必须唯一 |
| `/model default` | 恢复 Pi 默认模型 |
| `/models` | 显示当前本机可用模型目录 |
| `/models refresh` | 修改 Pi 配置后，重新读取可用模型 |
| `/thinking` | 选择当前模型支持的思考强度 |
| `/thinking high` | 设置 high；当前模型不支持时会提示 |
| `/thinking auto` | 恢复默认思考强度；`/think` 是别名 |
| `/new` | 新建对话，旧对话保留在历史记录 |
| `/clear` | 同样新建对话以重置上下文，不删除历史 |
| `/resume` | 打开历史会话列表，选择继续 |
| `/fork` | 复制当前会话与上下文，开一个分支 |
| `/name 模拟电路复习` | 重命名当前对话 |
| `/status` | 显示当前模型、思考强度、工具模式和运行状态 |
| `/abort` | 请求停止正在执行的回复；`/stop` 是别名 |
| `/settings` | 打开 Pi Agent 设置 |
| `/help` | 显示常用命令 |

模型与思考强度切换用于下一次请求。切换模型会把思考强度恢复自动。已有任务运行时先停止，避免中途更换模型或会话；停止已经完成的文件修改不会自动撤销。

### 原插件已有的上下文命令

| 命令 | 用法 |
| --- | --- |
| `/current 你的要求` | 把当前笔记加入上下文，再执行要求 |
| `/links 你的要求` | 把当前笔记的出链相关内容加入上下文 |
| `/backlinks 你的要求` | 把反向链接相关内容加入上下文 |
| `/search 关键词` | 使用相关搜索内容构建上下文 |
| `/context show` | 查看准备发送的上下文包，不调用模型 |
| `/compact` | 压缩会话上下文；这个操作会调用模型 |

终端版 Pi 的所有 TUI 功能不会自动出现在 Obsidian 中。登录、退出登录和安装 Pi 扩展等仍在电脑终端的 Pi 中完成。可用模型来自你的本机配置，手册不硬编码一份容易过期的型号名单。

### 可以直接复制的要求

先打开目标笔记，再发给 Pi：

```text
/current 保留我的原意，将这篇课堂笔记整理成“要点—推导—例题—待解决问题”。保留公式、链接和 publish: false，不确定的内容列为待核实。
```

```text
/current 检查公式的量纲、符号定义和适用假设。先列出问题和依据，不改文件。
```

```text
请读取收件箱.md，把有关 MOS 管的条目整理为一篇新笔记，保存到微电子笔记/MOS复习.md。使用已有笔记的双向链接，publish: false。完成后列出改动文件，不部署。
```

```text
/backlinks 找出哪些关联笔记重复解释了同一概念，建议一个合并方案，先不要删除或移动文件。
```

大规模整理前先提交 Git，或让 Pi 先给方案。它处理笔记时，相关内容会发送到你已经配置的模型提供方；`publish: false` 只控制博客输出，并不阻止你主动让 Pi 读取该笔记。

## 博客工作台与 pnpm 命令

按 `Ctrl+Shift+H` 返回 [[00-博客工作台]]。按钮在博客项目根目录运行。命令输出按钮可以查看进度、失败原因和实际预览地址；端口占用时实际端口可能不是 4321。

| 按钮 / 终端命令 | 功能 |
| --- | --- |
| 新建 / `pnpm run new-post "微电子笔记/标题" --kind=course` | 创建课程笔记，默认不公开 |
| `--kind=note` / `experiment` / `essay` | 普通 / 实验 / 随笔结构 |
| 启动预览 / `pnpm dev --host 127.0.0.1` | 启动本机开发预览 |
| 打开预览 | 浏览器打开当前实际预览地址 |
| 停止预览 | 停止由工作台启动的预览进程 |
| 检查 / `pnpm check` | Astro 内容与类型检查 |
| 构建 / `pnpm build` | 生成博客、搜索索引和字体资源 |
| 发布 / `pnpm deploy` | 执行现有部署流程：构建、Git 提交并推送 |
| 命令输出 | 查看运行日志 |

在 VS Code 或 PowerShell 中运行时，先进入项目：

```powershell
cd D:\AstroBlog\mizuki
pnpm run new-post "微电子笔记/MOS复习" --kind=course
pnpm dev --host 127.0.0.1
```

终端启动的预览用 `Ctrl+C` 停止；工作台停止按钮只管理工作台自己启动的进程。构建和部署前停止预览，避免争用构建缓存。`pnpm deploy` 会按原流程提交仓库中的其他修改，执行前在 VS Code 的源代码管理中检查改动。

## 公开规则与发布前检查

```yaml
title: "MOS复习"
published: 2026-10-09
publish: false
draft: false
tags: [微电子, 模拟电路]
category: 微电子笔记
```

- `publish: false`：不进入博客页面、RSS 和搜索索引，可以提交 Git。
- `publish: true` 且 `draft` 不为 `true`：允许进入博客，还需要有效标题和日期。
- 旧文章没有 `publish` 属性时保留原来的公开行为。
- 改成不公开后，已有线上文章需要重新部署才会消失。
- 公开文章链接到私密笔记时，博客显示普通文字；**嵌入私密笔记会阻止构建**，需要先去掉嵌入或明确公开目标笔记。
- 图片和图纸通过实际引用进入博客；别把含私人信息的图直接嵌入公开文章。
- 私密 Git 内容在公开 Git 仓库中仍可被看到；这里只承诺博客不展示。

发布顺序：打开目标文章 → 确认属性和所有嵌入 → 切换公开 → 启动并检查预览 → 停止预览 → 检查 → 部署。工作台不会自动替你发布。

## 日常维护与排错

- **Pi 没有 `/model` 提示**：确认 Pi Agent 和 Mizuki 工作台都启用。插件升级后如果接口改变，需要重新适配工作台；先用 Pi 的 Model 按钮也能选择。
- **模型列表没有新模型**：确认电脑 Pi CLI 配置能使用，再输入 `/models refresh`。模型密钥留在原配置位置，不写进笔记或 Git。
- **Pi 没有修改文件**：检查工具模式是否为 Edit、是否选对笔记，并明确给出目标路径。
- **预览没有私密笔记**：这是 `publish: false` 的预期行为。在 Obsidian 中正常阅读和编辑即可。
- **公式命令没候选**：进入编辑视图，在 `$...$` 或 `$$...$$` 中输入 `\` 加字母，检查 LaTeX Complete 已启用。候选只补命令名称，参数继续填写。
- **公式片段没展开**：切换英文输入，进入数学模式，按 `Tab`；检查 LaTeX Suite 已启用。
- **图在博客里缺失**：保存源图，检查 SVG 导出，检查嵌入路径；不要只留下 Canvas 或插件私有数据。
- **预览样式旧了或提示依赖过期**：停止重复的 dev 进程，重新启动一次，再刷新浏览器。Obsidian 的插件、聊天记录和隐藏配置已排除在博客热更新监听之外。
- **找不到功能**：`Ctrl+P` 搜索命令，不需要记下每个插件的快捷键。

插件升级前保留 Git 和 `.obsidian` 备份。日常不需要启动所有绘图编辑器；文本写作时关闭不用的绘图标签，保持少量常用标签页即可。

## 启动速度与插件加载

已安装现成的 **Lazy Loader**。在「设置 → Lazy Loader」可以为每个插件选择 Instant、Short delay、Long delay 或 Disable plugin。

- 写作必需的目录导航、LaTeX Suite、LaTeX Complete、QuickAdd、Templater、Pi 和博客工作台立即加载。
- Omnisearch 在约 2 秒后加载；这段时间仍可使用原生搜索。
- Excalidraw 和 Draw.io 在约 5 秒后加载，插件之间另有少量错峰间隔。刚启动时绘图命令可能暂未出现。
- 启动时恢复上次工作区，不再强制打开博客工作台。需要工作台时点击左侧房子图标，或 `Ctrl+P` 搜索「打开博客工作台」。

下次完整重启开始使用此配置。要持续关闭某个插件，请在 **Lazy Loader 设置**中选 Disable plugin；只在第三方插件页面关闭，可能会被 Lazy Loader 再次启用。卸载 Lazy Loader 后，需要在第三方插件页面重新启用之前延迟加载的插件。

原生启动耗时统计入口是「设置 → 常规 → 高级」中的秒表按钮。延迟加载减少的是最初进入编辑器的等待，绘图和搜索插件仍需要在后台完成初始化；尚未测量本机重启后的具体提速幅度。

## 自行接入外部文件夹

已安装 **Folder Bridge 2.15.4**，这是现成的第三方插件，尚未进入官方社区插件市场。你可以完全通过设置管理目录，不需要修改脚本。

1. 打开「设置 → Folder Bridge」，选择 **Add mount point**（也可使用插件的文件夹加号入口）。
2. 选择 **Local filesystem**。Real path 填实际 Windows 文件夹，例如 `D:\课程笔记`；Virtual path 填左侧显示的位置，例如 `外部资料/课程笔记`。
3. 验证路径并添加，需要编辑时不要勾选只读。只有明确添加的外部路径会被接入。
4. 在左侧原生「文件列表」展开该虚拟目录，打开 Markdown。保存会写回原来的文件夹。Notebook Navigator 仍保留；若它没有立即显示新目录，先使用原生文件列表。

外部文件保留原地，不会复制到博客 posts，也不会因这个虚拟挂载自动进入博客构建、Git 提交或发布。博客工作台的公开开关和新建文章分类只处理实际博客内容。要发布外部笔记，需要自行把要发布的内容和附件放入 posts。

不要把虚拟显示路径当作实际磁盘路径传给终端或 Pi CLI；涉及外部笔记时明确提供真实路径。外部目录下的新建、编辑与附件路径由 Obsidian 和 Folder Bridge 处理，博客新建按钮仍写入 posts。

已忽略 `.git`、`node_modules`、`.obsidian`、`.astro`、`dist` 和 `.cache` 等目录，减少扫描开销。建议只接入笔记文件夹，并用插件的文件过滤、文件数量上限控制大型目录。该版本作者尚未完成 Windows 原生编辑与保存兼容性验证，首次使用先接入一个小目录确认自己的工作流程。

原生可用 Windows 符号链接或目录联接，但没有 VS Code 式的「添加文件夹到工作区」界面。Obsidian 官方列有链接监听、跨盘移动和同步限制，本仓库没有创建这类链接。

插件说明：[Lazy Loader](https://github.com/alangrainger/obsidian-lazy-plugins)、[Folder Bridge](https://github.com/tescolopio/Obsidian_FolderBridge)、[原生目录链接限制](https://obsidian.md/help/symlinks)。
