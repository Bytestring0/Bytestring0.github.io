# 处理器的工作原理

软件的运行其实就是运行软件的代码，代码会被翻译成一条条指令，装载到一个程序计数器中，然后交由处理器执行。
处理器处理的是一条条指令，对于每个指令来说分为操作码和操作数，这很好理解。操作码决定了处理器执行什么操作，操作数决定要操作哪些数据。
程序计数器用于记录当前执行到哪个指令，一般状态下会顺序执行，当然可以通过指令对程序计数器进行操作，这样就可以实现循环。
```
0: li r0, 10   # 这里是十进制的10
1: li r1, 0
2: li r2, 0
3: li r3, 1
4: add r1, r1, r3
5: add r2, r2, r1
6: bner0 r1, 4
7: bner0 r3, 7
```

> 尝试继续执行指令, 记录寄存器的状态变化过程. 你发现执行到最后时, 处理器处于什么样的状态? 上述数列的求和结果在哪个寄存器中?

将r0,r1,r2,r3进行初始化，然后r1<-r1+r3，r2<-r2+r1，接着一直执行4-6直到r0==r1。
在这个例子中，r0用于条件判断，r1在每次和r2相加前会加r3，r3决定了r1数列的公差，r2增加r1，作为累加器的作用，求和结果保存在这里。最后程序会反复执行7。

> 尝试用上述指令编写一个程序, 求出10以内的奇数之和, 即计算1+3+5+7+9. 编写后, 尝试列出处理器状态的变化过程, 以此来检查你编写的程序是否正确.

只需将r0初值设为11，r1初值设为1，r3初值设为2，指令4和指令5交换顺序即可。

这其实就是编程
```
r0 = 10
r1 = 0
r2 = 0
r3 = 1
do{
    r1 += r3
    r2 += r1
}while(r1!=r0)
```

# 指令集架构

指令集架构（Instruction Set Architecture），简称ISA。ISA规定了具体有哪些指令，指令的规范是什么，有哪些需要实现的功能等等，是一套对于处理器的规范。在使用编程语言写程序的时候，编译器负责了将程序转化为对应ISA（x86，ARM）的指令。对于编译器来说，应该使得两者语义等效，然而两者的状态不一定相同，底层执行上也不太一样，特别是对于未定义行为。

# 如何搭建这样的处理器

在思想上我们已经搭建了这样的处理器，也就是ISA，我们可以根据ISA的规范写出像样的程序，我们也可以增改这样的ISA实现更多功能。
我们知道处理器是由电路，主要是数字电路实现的。要实现这样的处理器，其实就是在实现处理这些指令的电路模型。具体来说，对于`add`指令，我们需要加法器，对于`li`指令，我们需要一些寄存器，为了使得程序可以自动执行，我们可能需要一个可以自己递增，也可以写入数据的计数器。当然，更重要的是将这些指令翻译成电路能看懂的二进制，然后通过组合逻辑译码的方式确定当前指令，通过时序逻辑来决定当前状态和状态的转移。
